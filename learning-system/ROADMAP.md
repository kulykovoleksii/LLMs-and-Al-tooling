# Інтенсивний маршрут на 4 тижні

Кожен тиждень відповідає одному тижню програми та її deliverable з брошури.
Працюй близько 30 зосереджених годин на тиждень: орієнтир — 6 годин на день,
5 днів на тиждень, плюс перерви. Базові інструменти вивчаються в процесі
побудови capstone, а не окремим багатотижневим підготовчим етапом.

## День 0 — налаштування (до 3 годин)

Створи репозиторій або папку capstone, налаштуй Git, середовище, тести й форматування.
За 60–90 хвилин без AI перевір Python/JSON/exception базу. Прогалини закривай
під час побудови проєкту, не витрачай на них окремий тиждень.

## Тиждень 1 — надійні LLM-виклики

**Ціль брошури:** classifier workflow із валідованими, schema-conformant даними.

- **День 1:** tokens, context window, cutoff, next-token prediction; baseline
  без LLM, модельний API клієнт із timeout і безпечним зберіганням ключа.
- **День 2:** prompt structure, schema-first output, JSON parsing і validator.
- **День 3:** sampling, вибір моделі, retries/fallback; перевірки на timeout,
  помилку провайдера та невалідний вихід.
- **День 4:** 20–30 синтетичних прикладів; порівняй правила й LLM, розбери
  hallucination, sycophancy та неоднозначні запити.
- **День 5:** виправ регресії, запиши prompt/schema/model version, короткий
  decision note та демо.

**Deliverable:** валідований classifier. **Gate:** жоден невалідний вихід
не проходить тихо; ти можеш пояснити, коли LLM не потрібна.

## Тиждень 2 — агенти й tool calling

**Ціль брошури:** агент класифікує запит, обирає дію та виконує tool call
із відповідними human checkpoints.

- **День 1:** planner/executor проти deterministic flow; визнач, де агент
  виправданий, і намалюй межі доступу.
- **День 2:** типізовані tool contracts, structured errors, idempotency;
  агент поки лише пропонує дію.
- **День 3:** act–observe loop, обмеження кроків, state, timeout і stop condition.
- **День 4:** checker/verifier, allowlist, human approval перед записом,
  обробка недовірених tool results/retrieved content.
- **День 5:** adversarial self-tests, тести відмови, трасування без секретів,
  демо й короткий опис загроз.

**Deliverable:** обмежений агент із людським checkpoint. **Gate:** не може
виконати невідомий інструмент, нескінченно працювати чи зробити непідтверджену
побічну дію.

## Тиждень 3 — контекст, retrieval і fine-tuning

**Ціль брошури:** агент працює з retrieved knowledge; рішення fine-tuning
проти baseline задокументоване.

- **День 1:** контекстний бюджет, chunking, metadata, freshness; підготуй
  невеликий публічний/синтетичний корпус.
- **День 2:** keyword retrieval baseline; відповіді мають посилатися на
  знайдені джерела або явно abstain.
- **День 3:** embeddings/vector search лише якщо baseline має виміряні недоліки;
  порівняй релевантність top-k на тих самих запитах.
- **День 4:** перевір деградацію контексту, stale/missing docs та prompt
  injection у документах; зафіксуй невдалі приклади.
- **День 5:** decision memo retrieval/context/prompt vs fine-tuning: очікувана
  користь, дані, ризики та критерій успіху. Fine-tuning не запускай «про всяк
  випадок».

**Deliverable:** retrieval із керованим контекстом і документованим рішенням.
**Gate:** система не видає непідтверджене знання за факт і може відмовити.

## Тиждень 4 — оцінювання та hardening

**Ціль брошури:** evaluation harness виявляє регресію і gate-ить зміну агента
з тижня 2.

- **День 1:** сформуй golden set щонайменше з 30 типових, граничних,
  неоднозначних і відмовних прикладів; визнач rubric і pass/fail.
- **День 2:** реалізуй repeatable evaluation command і машинні перевірки схем/
  критичних властивостей.
- **День 3:** порівняй agent trajectories, збережи representative failures;
  LLM-as-judge — лише додатковий сигнал із людською перевіркою.
- **День 4:** додай версії промпту/моделі, latency, приблизну вартість,
  ліміти кроків, caching лише якщо виміряно його користь, escalation/fallback.
- **День 5:** запусти regression suite до/після зміни агента, усунь
  найважливіші підтверджені проблеми, підготуй README та 5-хвилинне демо.

**Deliverable:** evaluation harness, що виявляє/блокує регресію, і
демонстрований capstone. **Gate:** інша людина може запустити його за README;
ти можеш пояснити метрики, невдалі кейси й обмеження.

## Якщо курс оголосять раніше або пізніше

- **Раніше, ніж завершено місяць:** припини додавати нові функції; зроби
  коротку діагностику, повтори слабкі теми й пріоритезуй завдання курсу.
- **Дата невідома після місяця:** перейди на 2–3 години підтримки з
  [операційного посібника](OPERATING_SYSTEM.md).
- **Залишилось 2–4 тижні:** повтори по одному тижню програми, пройди усний
  залік і підготуй питання викладачам; не починай великий новий проєкт.
